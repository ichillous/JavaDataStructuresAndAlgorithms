# Exercises with evidence

Use the [catalog](catalog.md) to find source and corresponding tests. Complete each exercise by writing down a contract, providing a hand-worked example, implementing the change, adding a regression test and stating the time and space costs. The hints below describe a direction, not a required implementation. Predict first; then compare with the [worked solutions and reasoning](solutions.md).

| Exercise | Input or scenario | Success criteria and hint |
| --- | --- | --- |
| Dynamic-array insertion | Insert into an empty list, then insert at the front, middle and `size` | Match `ArrayList`; reject negative indices and indices above `size`. Trace the direction of the shift so values are not overwritten. |
| Queue wraparound | Enqueue, dequeue enough to move the head, then enqueue until growth occurs | Match `ArrayDeque` before and after growth. Logical order must survive copying from two physical array segments. |
| Iterator contract | Create an iterator, mutate its collection, then call `next` | Test the documented fail-fast policy, exhaustion and unsupported `remove`. A value replacement may differ from a structural change; read the API contract. |
| Adversarial hashing | Give many distinct keys the same hash code; also use a key whose hash is `Integer.MIN_VALUE` | Lookup, replacement, removal and resizing must match `HashMap` under the repository's non-null policy. Collision-heavy operations are linear, not guaranteed constant time. |
| Binary-search boundaries | `[1, 2, 2, 2, 5]` with targets `0`, `2`, `4`, `6` | `upperBound - lowerBound` gives the occurrence count. State that input must be sorted; do not hide an O(n) validation scan inside an advertised O(log n) search. |
| Sorting oracle | Empty, all-equal, ascending, descending, duplicate-heavy and extreme integer arrays | Compare every sort to `Arrays.sort` on a copy. Check that length and element multiplicities are preserved. Explain why subtraction is unsafe for comparing arbitrary `int` values. |
| Tree deletion | Delete a leaf, a one-child node, a two-child root, then an absent key | Compare inorder contents and size with `TreeSet` after every operation. Verify AVL balance after both insertion and deletion, including all rotation directions. |
| Trie pruning | Add `""`, `"car"`, `"cart"`, `"cat"`; remove `"car"` and then `"cart"` | Preserve `"cat"`, distinguish whole-word membership from prefix existence, and respect the result limit. A node's end-of-word flag is independent of whether it has children. |
| Disjoint-set model | Repeatedly connect random vertex pairs | Match a simple connected-component reference. A repeated union must not reduce the component count. The physical representative is an implementation detail. |
| Fenwick range sums | Initialize `[2, -1, 4, 3]`, add `5` at index `1`, and query `[1, 3)` | Compare prefixes and ranges with a simple array after each point update. Invalid ranges must fail; an overflowing update must leave every previously queryable sum unchanged. |
| Graph reachability | A graph containing a cycle, an isolated vertex and disconnected components | BFS and DFS visit only reachable vertices, once each. Check paths by validating each consecutive edge rather than demanding one arbitrary shortest path when ties exist. |
| Dijkstra oracle | Generate small graphs with nonnegative weights | Compare all distances to a small Floyd–Warshall reference. Include unreachable vertices, zero-cost edges and parallel edges; test the documented arithmetic policy separately. |
| Minimum spanning forest | Two disconnected weighted triangles plus an isolated vertex | Verify acyclicity, component preservation, selected-edge count and total weight. For tiny graphs, enumerate candidate forests independently. |
| Greedy counterexample | Coin denominations `[1, 3, 4]`, amount `6` | Largest-coin-first chooses three coins; the optimal answer uses two. Contrast this failure with earliest-finishing activity selection, whose exchange argument establishes optimality for that problem. |
| Knapsack loop direction | One item of weight `2`, value `3`, capacity `4` | A 0/1 solution returns `3`, not `6`. Explain how an ascending capacity loop accidentally permits reuse. Check zero-weight items against the documented contract. |
| String matching | Text `"aaaaa"`, pattern `"aaa"`; then an empty pattern | Find overlapping starts `[0, 1, 2]`. Explain the prefix-function fallback and the chosen empty-pattern behavior. UTF-16 indices are not grapheme-cluster indices. |
| Unique permutations | `[1, 1, 2]`, then `[]` | Produce exactly three unique permutations in the first case and one empty permutation in the second. Track positions as well as values. |
| N-Queens verification | Solve sizes `0`, `1`, `2`, `3`, `4` | Validate every returned board independently for row, column and diagonal conflicts. Check the empty-board convention and keep enumeration sizes small. |
| Selection versus sorting | `[7, 2, 9, 4, 4, 1]` with `k = 2`; then all-equal, ascending and organ-pipe arrays of 10,000 values | Match the sorted copy at every valid `k` and leave the input unchanged. Trace the three-way partition, and explain why a fixed pivot rule alone is quadratic in the worst case. |
| Stable top-k and merge | Records `(key, id)` with repeated keys and `k = 0`, `k = n`, `k > n`; lists `[[1, 3, 5], [1, 2], [], [5]]` | Equal keys keep arrival order in `smallestK`; in `mergeSorted` the lower list index wins ties; compare with a stable sort of the concatenation. A list such as `[2, 1]` must be rejected. |
| Non-comparison sorts | Ages in `[0, 150]`, ints near `Integer.MIN_VALUE` and `Integer.MAX_VALUE`, and a range of 2^20 + 1 | Match `Arrays.sort` on a copy. Expect `IllegalArgumentException` and an unchanged array when the range is too wide. Explain why radix needs the sign-bit flip. |
| Stable multi-key sort | Records `(city, name)` with many equal cities | Sort by name, then stably by city, and match `Arrays.sort(copy, comparator)`. Show an unstable sort breaking the name order. |
| Histogram stack | Heights `[2, 1, 5, 6, 2, 3]`, then `[Integer.MAX_VALUE, Integer.MAX_VALUE]` | Compare with an O(n²) scan over all ranges using the minimum height. The second case needs a `long` area; explain why each index is pushed and popped once. |
| Difference-array overflow | Base `-Long.MAX_VALUE` with two `+Long.MAX_VALUE` adds over the same range | The prefix leaves `long` range but the final value fits. Compare with a `BigInteger` model and explain when the exact implementation must throw `ArithmeticException`. |
| Backward-shift deletion | Many keys with one shared hash code, plus keys whose probe path wraps past the end of the table; remove the cluster head, a middle key, then look up the rest | Match `HashMap` after every removal. A lookup must never stop at a hole left by a removal; explain which entries may move into the hole and why an entry whose home lies after the hole must stay. |
| Order statistics | Insert `30, 10, 50, 20, 40`; probe `rank` with `5`, `25`, `60`; `select` every rank `0..4`; count `[15, 45)` and `[45, 15)` | `rank` counts keys strictly below the probe whether or not it is stored; `select(rank(k)) == k` for every stored key; `countInRange` equals `TreeMap.subMap(from, to).size()` and is 0 for a reversed range. Explain why every rotation must keep both nodes' subtree sizes correct. |
| Red-black insertion trace | Insert `1..5`, then separately `5, 4, 3, 2, 1` | Name each rotate-left, rotate-right and color flip. After every step check BST order, left-leaning red links, no red node with a red child, equal black height and a black root, then draw the 2-3 tree each version encodes. |
| Bloom filter false positives | Size a filter with `forExpectedInsertions(1000, 0.01)`, add 1000 seeded strings, then probe 100000 absent strings | Every added string must be reported present (no false negatives). Compare the observed false-positive rate with `estimatedFalsePositiveRate()`; do not assert an exact count. Explain why deletion is unsafe. |
| Count-Min overestimates | Stream 50000 Zipf-like items into `withErrorBounds(0.01, 0.01)` | Compare with a `HashMap` of exact counts: `estimate` is never below the true count, and most items are within `epsilon * totalCount()`. A failed overflowing add must leave estimate and total unchanged. |
| Sparse-table overlap | Build the rows for `[4, 6, 1, 5, 7, 3, 8]`, then answer every `[from, to)` with two blocks | Match a scan for every range, including empty ones (no value) and an all-`Long.MAX_VALUE` array. Store sums instead of minima and find the first range where overlapping blocks double-count. |
| Lazy range additions | `[1, 2, 3, 4, 5]`: add `+2` on `[1, 4)`, then `+10` on `[2, 5)`, then query `[3, 4)`; separately, start at `Long.MIN_VALUE` and add `Long.MAX_VALUE` to the whole range twice | Compare every range sum with a `BigInteger` model after each step. Name the nodes holding pending additions. A rejected addition must change no element, and a sum must throw only when its true value leaves `long` range. |
| A* heuristic audit | A grid with blocked cells, Manhattan distance, then a heuristic that overestimates one cell | Distances equal Dijkstra's with the consistent heuristic; the overestimate is rejected when the search expands that cell (it then scans an edge with h(u) > w(u, v) + h(v)); place it once on the shortest route and once on a dead end, and explain why a scanned-edge check cannot catch violations on edges never explored. |
| Floyd-Warshall boundaries | Path `0 -> 1 -> 2` with weights `Long.MAX_VALUE` and `-1`, then `Long.MAX_VALUE` and `1` | The first gives `Long.MAX_VALUE - 1`; the second must throw rather than wrap. Add a negative cycle that vertex 0 cannot reach and explain why all-pairs rejects it while Bellman–Ford from 0 does not. |
| Cut vertices and bipartiteness | Graphs on at most ten vertices, including loops, isolated vertices and a bowtie | Compare `articulationPoints` with a remove-and-recount-components oracle. Compare `bipartition` with all 2^V colorings and validate an `oddCycle` witness edge by edge; exactly one of the two must be present. |
| Euler path validation | Directed `0->1->2->0, 2->3`; undirected star `0-1, 0-2, 0-3`; an undirected loop at a vertex with one other edge | Check degree conditions and connectivity independently, then replay the returned path against an edge multiset. A loop adds 2 to degree but is a single edge. |
| Max-flow oracle | Random networks with at most 8 vertices, fixed seed, parallel edges and self-loops | Compare the flow value with the minimum capacity over every s-t vertex cut. Verify capacity, conservation and that the returned `sourceSide` has capacity equal to the value. |
| Matching oracle | Random bipartite graphs with at most 7 vertices per side and duplicate edges | Compare the matching size with a bitmask brute force; check each vertex is used once and every pair is an input edge. |
| Tree LCA oracle | Random trees with up to 200 vertices, every vertex pair, several roots | Compare `lca`, `distance` and `kthAncestor` to a naive parent walk. Reject a cycle, a self-loop, a disconnected graph and a directed graph rather than answering. |
| Tree diameter | A 100,000-vertex path, a star and a tree with two tied diameters | The path length must equal the all-pairs BFS maximum and every consecutive pair must be an edge. Check the documented smallest-vertex tie rule separately, and ensure no recursion proportional to V. |
| Verified rolling hash | Find two distinct equal-length strings with the same Rabin–Karp hash (base 257, modulus 2^31 − 1) by seeded random search | `rabinKarpFindAll` must not report the impostor; compare against `kmpFindAll`. Explain why verifying each hash hit makes the answer exact, and why the running time still depends on the input: each genuine or spurious hit costs O(p), so k reported matches cost O(t + p + k·p) when spurious hits are rare, and with the fixed base and modulus a crafted input can force O(t·p). |
| Palindrome ties | `"babad"`, `"cbbd"`, `"abc"`, `""` | Match a brute-force search that keeps the earliest start among equal lengths; `""` gives `Span(0, 0)`. Explain how Manacher reuses a mirror center inside the rightmost palindrome. |
| Dictionary matching | Patterns `he`, `she`, `his`, `hers` on `ushers`; then nested patterns `a`, `aa`, `aaa` on `aaaa` | Compare with one `kmpFindAll` per pattern, sorted by start then length. Explain why a match found through an output link (`he` inside `she`) is not missed. |
| Suffix array oracle | `banana`, the empty string, and random strings over three letters | Compare ranks with sorting `substring(i)`, LCP with direct prefix comparison, and distinct substrings with a `HashSet` for n <= 30. Explain why `n(n+1)/2 - sum(lcp)` counts distinct substrings. |
| Reconstruction tie rules | LCS of `"ABCBDAB"` and `"BDCABA"`, then flip the `>=` up/left test to `>` in a copy | Both results are common subsequences of length 4 but may differ. Verify each with a subsequence check and explain why a pinned string is only valid together with its tie rule. |
| Edit script replay | `"kitten"` to `"sitting"`, then random short strings over a 3-letter alphabet with a fixed seed | Replaying the steps over the source yields the target, and the non-match count equals the edit distance. Explain why INSERT and DELETE cursors differ from MATCH. |
| Coin loop order | Coins `[1, 2, 5]` with amount 5, then amount 3 with coins `[1, 2]` | Compare with brute-force enumeration of multisets. Swap the loops to count ordered sequences, show the answer changes from 2 to 3 for the second case, and explain why the coin loop must be outer. |
| Huffman against brute force | Frequencies `[5, 9, 12, 13, 16, 45]`, then `[1, 1, 2, 4]` and `[0, 7, 0]` | Total cost must be 224 for the first case; compare with brute force over length vectors satisfying Kraft for at most six symbols. Check a single used symbol, all zeros, and that `canonicalCodes` output is prefix-free. |
| Modular arithmetic at the limit | `modPow` and `modInverse` with moduli `Long.MAX_VALUE`, `2^62 + 1` and 97, random bases including negatives | Match `BigInteger.modPow` and `modInverse` exactly. Show that `a * b % m` gives a different answer for `m = 2^62 + 1`, `a = b = 2^62`. |
| Primality against a reference | `isPrime` on 561, 41041, 3215031751, `2^61 - 1`, `Long.MAX_VALUE` and 20,000 seeded longs | Compare with `BigInteger.isProbablePrime(50)`; every Carmichael number and strong pseudoprime must be reported composite. Explain why a Fermat test alone fails. |
| Shuffle uniformity | Shuffle `{1, 2, 3}` 60000 times with `new SplittableRandom(0x5A3)` and count each of the six orders | Every order must be within 1/6 plus or minus 0.01. Then replace `nextInt(i + 1)` by `nextInt(n)` and show the counts become visibly uneven. Never assert exact counts. |
| Weighted draws | Build an `AliasTable` for `[1, 0, 3]` and draw 60000 indices with a fixed seed | Frequencies near `[0.25, 0, 0.75]` within 0.01, and index 1 never appears. Rebuild the probabilities exactly from the table's cutoffs and aliases and compare with `probability(i)`. |

## A repeatable review exercise

Choose a structure and intentionally introduce one defect: skip resetting the queue head on clear, fail to decrement tree size, or remove a trie prefix with its descendants. Confirm that a relevant test detects it, then restore the correct implementation. This is a local learning exercise; do not commit intentionally broken code.

For an extension, add a small, justified API such as a persistent structure or a skip list. Decide behavior before implementation: nulls, index boundaries, mutation, overflow and empty results. Add the extension to the catalog and explain when it is preferable to an existing JDK type. More classes alone do not make a stronger learning resource.

## Deeper checkpoints

- Compare a ring deque with `ArrayDeque` after both-end operations and wraparound growth.
- Compare LRU eviction with an access-order `LinkedHashMap`; distinguish a miss, a hit and replacement.
- Find all directed SCCs using an independent reachability matrix; remove each undirected edge to verify bridges.
- Compare signed Bellman–Ford with exact-integer Floyd–Warshall on tiny graphs. Test a reachable negative cycle separately from an unreachable one, and distinguish it from finite-distance overflow.
- Verify Kadane's maximum subarray against all intervals and its earliest-start/earliest-end tie policy; compare window maxima to direct scans.
- Verify inversion counts by enumerating pairs, including equal values and a descending array whose answer exceeds int range.
- Verify subset witnesses by their indices, not just values. For at most 30 inputs, the chosen inclusion mask is the smallest possible mask, with index zero as the least-significant bit.
- Validate every solved Sudoku row, column, box and given independently. An invalid or unsolvable input must not leave partial mutations; aliased rows are malformed.
- Compare LFU eviction with a list model ordered by (use count, last-use tick); include replacements, removals, `clear` and a key that returns after eviction.
- Build a workload where LRU keeps the hot set but LFU keeps a stale favorite, then one where a scan flushes LRU but not LFU.
- For every probabilistic or randomized API, fix the seed, record it in the failure message, and test the one-sided guarantee (no false negatives, no undercount, uniform within a tolerance) rather than an exact count.
- List each documented size cap (`Integer.MAX_VALUE - 8` for array growth and DP tables, 2^30 Bloom bits, 2^25 sketch counters, 2^20 counting-sort range, 2^30 open-addressing slots, 2^29 lazy-segment-tree elements, 50,000,000 sieve limit, 16 Held–Karp cities) and the exception its violation throws. Explain why a smaller but still large input can run out of memory without tripping the guard.
