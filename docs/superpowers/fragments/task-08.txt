(b) COMPLEXITY ROWS
Target table: "## Data structures" in docs/complexity.md (columns: Implementation / operation | Time | Space and assumptions)
Place the rows directly after the `AvlTree` row.

| `RedBlackTreeMap` get/containsKey/put/remove | O(log n) worst | O(n) stored nodes, each with a color and a subtree size; height at most 2 log2(n + 1) - 1; put/remove recurse along one search path (O(log n) stack), get/containsKey are iterative |
| `RedBlackTreeMap` first/last/floor/ceiling, rank/select/countInRange | O(log n) worst | O(1), iterative; rank adds skipped left-subtree sizes, countInRange is rank(to) - rank(from) and cannot overflow |
| `RedBlackTreeMap` keys / height | O(n) | O(n) immutable snapshot plus O(log n) explicit stack / O(log n) recursion; height is not cached |

(c) SOLUTION-FINDER ENTRIES
Family: "Ordered keys and nearest-key queries"
Link to write for each: [RedBlackTreeMap](../src/main/java/io/github/ichillous/dsa/structures/RedBlackTreeMap.java), lesson [red-black trees](../data-structures/trees/red-black-trees.md)

- Problem heading: "Find the nearest stored key at or below (floor) or at or above (ceiling) a value while keys are inserted and removed"
  Technique: Balanced binary search tree ordered map (left-leaning red-black): RedBlackTreeMap.floorKey / ceilingKey. JDK: java.util.TreeMap#floorKey and #ceilingKey
- Problem heading: "Find the k-th smallest key, or how many keys are smaller than x, in a changing set (order statistics)"
  Technique: Order-statistic tree, a red-black tree augmented with subtree sizes: RedBlackTreeMap.select / rank. The JDK has no select; TreeMap.headMap(x).size() gives the rank without a logarithmic guarantee
- Problem heading: "Count the stored keys in a range [lo, hi) of a changing ordered set"
  Technique: Rank difference on a size-augmented balanced BST: RedBlackTreeMap.countInRange
